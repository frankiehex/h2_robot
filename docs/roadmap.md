# 实施路线图 —— 从仿真骨架到真机运行

- 版本：v0.1
- 日期：2026-07
- 关联：[`concept-design.md`](concept-design.md)（整线概念）、[`cell-control-design.md`](cell-control-design.md)（工位控制设计）
- 原则：**最小闭环先跑通，再复制铺开**。不要一上来就整线，先用 1 台臂 + 1 个任务把
  「看见 → 尝试 → 判定 → 复位 → 迭代」这条链打通，跑通了换品牌只是改驱动层。

## 阶段总览

```
阶段0 选型定点 ──▶ 阶段1 单臂空跑 ──▶ 阶段2 加视觉 ──▶ 阶段3 双臂互锁 ──▶ 阶段4 接PLC线体 ──▶ 阶段5 铺开整线
   (你,1天)        (你+我,3-5天)      (你+我,1周)      (你+我,3-5天)     (你+我,1周)        (迭代)
```

每个阶段有明确「完成判据」，达标才进下一阶段。

---

## 阶段 0 · 选型定点（决策，约 1 天）

**目标**：定下试点用哪台臂、做哪个任务、放哪。这一步决定我下一步写什么代码。

- [ ] **选试点臂**：建议 **UR**（RTDE 接口最成熟、生态最全、社区资料多），
      次选法奥（Python SDK 单位与本项目 Pose 一致，最省换算）。
- [ ] **选试点任务**：建议先做**放火腿(S3)**——单臂、取放类、有视觉需求但不接触敏感，
      最能验证「视觉偏差修正取料」这条主链。
- [ ] **定基座位置**：在 RoboDK（三品牌都支持）里把臂 + 工作窗口摆进去，
      逐格验证可达性/关节裕量/奇异点，**基座装哪、装多高在仿真里定死**。
- [ ] **备一台工作站**：一张 RTX 4090/5090 起步，跑视觉推理 + 控制 + 看板足够。

**完成判据**：确定了臂型号 + 任务 + 基座坐标 + 一台联网的控制主机。

> ⛳ 这是唯一卡在你这边的决策点。定了告诉我，我就按选定的品牌把驱动层填实。

## 阶段 1 · 单臂空跑（无视觉，你+我，约 3-5 天）

**目标**：程序能让真臂按示教点做「取→放」，先不接相机，用固定点。

**你做（硬件/示教）**
- [ ] 给臂拉网线到控制主机同网段，确认能 ping 通、能用官方示教器动。
- [ ] 装夹爪/吸盘，接到可编程 IO（大寰 DH / Robotiq 等带 SDK 的最省事）。
- [ ] 用示教器记录：HOME 安全岛、取料点、12 格放置点的 approach/pose/retreat，
      填进 `cellctl/config/grid_poses.yaml`（格式已定义好，照填即可）。

**我做（软件）** —— ✅ 三款驱动已填实，可直接联调：
- [x] 三款真机驱动的 `move_to`/`go_home`/`grip`/`read_pose` 已实现，含各家单位/姿态换算：
  - UR → `ur_driver.py`（米+旋转矢量；mm↔m、欧拉角→旋转矢量；moveL 带转弯区）
  - 法奥 → `fairino_driver.py`（mm+度透传；MoveL/MoveJ/SetDO；vel 为百分比）
  - 节卡 → `jaka_driver.py`（mm+弧度；linear_move(_extend)/joint_move/set_digital_output）
- [x] 混合车队配置示例 `config/fleet.example.yaml`（法奥+节卡+UR 同线，每工位一款）。
- [x] 单臂安全首触脚本 `smoke_test.py`（连接→读位姿→可选回HOME/夹爪，不碰产线）。
- [ ] **待你在真机上做**：装对应品牌 SDK（`ur_rtde` / `fairino` / `jkrc`），
      跑 `python -m cellctl.smoke_test --station <名> --config config/fleet.example.yaml` 首触。
- [ ] 加一层软件安全包络：工作空间限位、速度上限、急停看门狗（联调时按现场补）。

**完成判据**：`python -m cellctl.main --dashboard --config config/fleet.example.yaml` 驱动真臂，
看板 LIVE 实时显示三品牌并行，各臂稳定跑完取放并回 HOME，无碰撞。

## 阶段 2 · 加视觉（你+我，约 1 周）

**目标**：相机看见来料，程序把毫米级偏差 (dx,dy,dθ) 叠加到取料点。

**你做（硬件/光学）**
- [ ] 顶部固定装一台工业相机（海康机器人 SC 智能相机 / 或普通工业相机 + 上位机）。
- [ ] **打光**：加条形光/穹顶光 + 遮光罩，把环境光隔掉——这一步比调算法重要十倍。
- [ ] 夹一根标定针，配合走标定点采集数据。

**我做（软件）**
- [ ] 实现 `cellctl/vision/calibration.py` 的交互采集流程：拍棋盘格 → `solve_homography`
      → 走 4 点 → `solve_rigid_2d` → 存 `config/calibration/S3_ham.yaml`。
- [ ] 在 `cellctl/main.py` 里替换那处「真机视觉」的 `NotImplementedError`：
      加载标定 + `ContourLocator`，接进取料流程。
- [ ] 按现场打光把 `cellctl/vision/locator.py` 的 HSV 阈值/最小面积调稳，
      验证 `min_score` 低分跳过逻辑（来料异常不硬取）。

**完成判据**：故意把火腿在托板上摆偏 ±几 mm/几度，臂能修正并准确取到；
低置信度来料被正确跳过并记日志；看板显示实时视觉偏差。

## 阶段 3 · 第二台臂 + 互锁验证（你+我，约 3-5 天）

**目标**：上第二台臂（可换品牌，验证统一接口），跑真实区域互锁。

**你做**
- [ ] 布置第二台臂，物理上尽量让工作包络不重叠（第一层防碰撞：布局分离）。
- [ ] 若确有共享空间，在 `line.yaml` 定义共享 zone，两臂 `grid_zones` 都列上。

**我做**
- [ ] 若第二台是不同品牌，填对应驱动（接口已统一，上层不动）。
- [ ] 压测互锁：真机上验证共享区互斥、无死锁（对应 `tests/test_zone_lock.py` 的真机版）。
- [ ] 看板上确认 zone 锁表、步进前回 HOME 检查在真机时序下正确。

**完成判据**：两臂并行作业，共享区从不同时进入，节拍内互不干扰，无碰撞、无死锁。

## 阶段 4 · 接 PLC 线体（你+我，约 1 周）

**目标**：把仿真的线体换成真实步进输送线，控制器读到位信号、发步进指令。

**你做**
- [ ] 步进输送线 + 载具到位锁定传感器 + PLC（Beckhoff/西门子）。
- [ ] 设计**自动复位工装**：试完能自动恢复原状（带斜面/定位槽/重力回位），
      这是「无人闭环」的前提——没有它就得有人守着。

**我做**
- [ ] 实现 `cellctl/scheduler/state_machine.py` 里 `LineIO` 的 PLC 版
      （Modbus TCP / OPC UA 读到位信号、发步进指令），替换 `SimLineIO`。
- [ ] 对接安全链：急停、区域扫描仪减速、故障转 FAULT 的现场策略。

**完成判据**：全线走-停-走由真实到位信号驱动，控制器与 PLC 时序对齐，
FAULT 能被现场正确触发与复位。

## 阶段 5 · 铺开整线（迭代）

**目标**：从 1 个工位复制到 S1–S6 组装 + S7 切割 + 后段，逐步无人化。

- [ ] 按 `concept-design.md` 的工位表逐个复制「驱动 + 示教 + 视觉」模式。
- [ ] 接入 QC 门（视觉/称重/金检）与五级溯源（RFID/DataMatrix 聚合）。
- [ ] 看板扩展成整线总览（多工位状态、节拍热力图、产能实时曲线）。
- [ ] 按 `concept-design.md` §9 的三期计划推进（打通节拍 → 无人到箱 → 全线无人）。

**完成判据**：对齐概念设计的 ≥600 份/小时产能目标与分钟级召回能力。

---

## 贯穿全程（任何阶段都要守）

- **安全优先**：刀具/夹点工位一律物理防护罩 + 安全门锁（切割工位不适用协作免围栏）。
  RL/自动探索类动作（若未来引入）必须在软件层再包一层力/速度限制。
- **先仿真后现场**：任何新工位的可达性、节拍、姿态先在 RoboDK 验证再上线。
- **配置驱动**：网格行列、扫描顺序、zone、位姿全在 YAML，改产品尽量只改配置不改代码。
- **看板常开**：每个阶段都带 `--dashboard` 跑，状态一眼可见，出问题快速定位。
